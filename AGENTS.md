# Pipeline instructions

This repository converts official legislation into Markdown and Git history.
Read [DEVELOPMENT.md](DEVELOPMENT.md) for format invariants and operating rules,
[ARCHITECTURE.md](ARCHITECTURE.md) for modules, and [README.md](README.md) for CLI
usage. These documents are the technical context formerly kept in `CLAUDE.md`.

- Inspect branch, diff and status before editing. Existing research and changes
  may belong to another session. Stage only your own named files; preserve the
  human Git author. Do not publish just because a branch is checked out.
- Python 3.12+, English code/comments/docs, `src/legalize/` layout. Use a dedicated
  environment: other Legalize packages use the same import namespace.
- Country support/configuration: `src/legalize/countries.py` and `config.yaml`.
  Do not maintain a duplicate country count or assume country data is on disk.
- Paths are generated by `src/legalize/layout.py` and declared in `.legalize.yml`.
  Follow the published Legalize Format Spec (locally `../hub/SPEC.md` when present).
  Paths need not be flat. Dates are `datetime.date` internally.
- Output format, Git bot identity and legislative history are contracts. Do not
  change them or rewrite country history as incidental cleanup. Pipeline fixes
  must not create fictitious legislative amendments. Read the reprocess procedure
  for repairs and reconcile downstream data with a full local sync afterward.
- New countries follow [adding-a-country/README.md](adding-a-country/README.md),
  including discovery, format coverage and fidelity gates. Preserve `text_state`
  semantics; as-enacted text must not be advertised as consolidated law.
- Inspect `git worktree list` before removing `engine-*` directories or reusing a
  branch. This checkout may contain work that has not reached the default branch.
- Keep private consumer implementation details out of this public repository and
  its PRs/issues. Describe the public data contract instead.

## Validation

From this repo's Python environment, install development dependencies with
`python -m pip install -e '.[dev]'` when necessary. Run targeted tests first:

```sh
python -m pytest tests/test_layout.py
python -m ruff check src/ tests/
python -m ruff format --check src/ tests/
```

Use `python -m pytest tests/` for broad pipeline changes; read the current CI and
pre-push hooks for additional required checks. Pinning and lint rules live in
`pyproject.toml`. CLI bootstrap, reprocess, backfill and push operations can alter
public corpora; do not execute them to validate documentation or ordinary setup.
